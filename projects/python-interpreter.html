Building a Python Interpreter

Exploring how software can process custom instructions, from calculations to academic advising rules.

For this team project, we built a small interpreter in Python that reads instructions, organizes them into a structure the computer can understand, and executes operations such as calculations and variable assignments.

Project Overview

An interpreter is software that reads instructions written in a programming language and carries out their meaning.

Our team built an interpreter for a small custom language supporting variable assignments, arithmetic expressions, print statements, and multiple statements. The interpreter processes the instructions through separate components for lexical analysis, parsing, and execution.

I was responsible for the parser and AST, which organize the instructions so the interpreter can process them in the correct structure and order. I also collaborated with my teammates on testing, documentation, and the project demonstration.

Real-World Application: Academic Advising Systems

Universities use software to help students and academic advisors understand course prerequisites, degree requirements, and progress toward graduation.

Although students and advisors may interact with these systems through forms, buttons, and menus, the application must process academic rules behind the scenes.

A custom rules interpreter could help an application evaluate a limited set of predefined academic requirements. For example, a course-planning tool could calculate remaining credit hours or, with additional functionality, determine whether a student meets the prerequisites for a particular course.

How the Interpreter Works

The interpreter processes written instructions through several connected components.

1. Lexer

Breaks source code into recognizable pieces called tokens.

Developed by a teammate.

2. Parser & Abstract Syntax Tree

Organizes the tokens into a structured representation of the instructions. The parser also applies the language's grammar and arithmetic precedence rules.

My individual contribution.

3. Interpreter

Evaluates the structured instructions and produces the program's output.

Developed by a teammate.
