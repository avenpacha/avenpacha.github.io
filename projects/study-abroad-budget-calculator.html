From CS640 Final Project to Portfolio Application

The Study Abroad Budget Calculator began as the final group project for my Advanced Database Systems course.

The original project focused on applying relational database concepts through a practical web application. Our group used MySQL as the database layer and Python Flask to connect the database to a browser-based interface.

The application provided functionality for managing students, study abroad programs, budgets, destination costs, tuition information, and other related records through an interconnected relational database.

After completing the course assignment, I decided to continue working on the project. Because of my previous professional experience in study abroad, I saw an opportunity to turn the academic database project into a more realistic tool for student financial planning and advising.

Why I Continued the Project

The original assignment gave me a strong database foundation, but I wanted to explore what the system could become when designed around the actual needs of students and study abroad advisors.

The Problem

Comparing study abroad programs can be difficult because the total cost extends beyond a single program fee. Students may need to consider tuition, housing, meals, airfare, transportation, living expenses, and other destination-specific costs.

Those estimates can also depend on the student's individual circumstances and program choices.

I wanted the application to organize this information in a way that helps students make comparisons while also creating useful context for future advising conversations.

Database & Application Architecture

The original CS640 project was designed around a relational MySQL database connected to a Python Flask application.

Relational Database

MySQL stores interconnected information about students, programs, budgets, destination costs, tuition rates, and related program data.

Flask Application Layer

Python Flask connects the browser interface to the database and handles application logic, routes, validation, and data operations.

Browser Interface

HTML, CSS, and JavaScript provide the student and administrator interfaces used to interact with the underlying application.

Relational Design

The database was designed using related tables and foreign-key relationships rather than storing all application information in a single table.

Constraints and validation help preserve referential integrity and keep data consistent as records are created, retrieved, and updated.

API and Database Operations

The Flask application processes requests and exchanges structured data with the database. JSON data from application requests is validated and processed before being used in SQL operations.

This gave me hands-on experience connecting front-end interactions, application logic, and relational database operations within the same system.

Expanding the Project Beyond the Course

After CS640, I continued developing the application independently rather than leaving it as a completed classroom project.

My goal shifted from demonstrating database functionality to creating a more complete application that reflects how students and advisors might actually use a study abroad budgeting system.

Student Planning Experience

Expanded the application to collect information relevant to a student's study abroad plans and budgeting needs.

Program Search

Improved how students explore available programs and filter options based on relevant program attributes.

Program Comparisons

Expanded the budgeting workflow so students can save and compare multiple study abroad options and their estimated costs.

Term-Specific Program Data

Extended the data model to better represent program offerings, deadlines, and costs that can vary by academic term.

Advising Workflows

Added functionality that organizes student planning information in ways that can support future advising conversations.

Public Portfolio Demo

Prepared and deployed an employer-facing version that demonstrates application workflows without exposing real student information.
