CS640 — Advanced Database Systems

Study Abroad Budget Calculator & Advising Platform

A full-stack web application that connects student financial planning with study abroad advising and administrative workflows.

This application began as my group's final project for CS640 Advanced Database Systems. We developed a database-backed web application using Python Flask and MySQL to manage study abroad program, student, budget, and cost information.

After the course ended, I continued developing the project independently, expanding it into a more complete platform designed around both the student planning experience and the administrative needs of study abroad offices.

From CS640 Final Project to Portfolio Application

The original course project focused on applying relational database concepts through a practical web application. Our group connected a MySQL database to a Python Flask application and browser-based interface.

During the course project, I contributed to database and application development, SQL integration, testing, debugging, and troubleshooting how information moved between the application and database. I also presented the completed project to our professor and graduate Computer Science classmates.

My previous professional experience in study abroad gave me a real-world perspective on the problem. Students need help understanding the complete financial picture of different programs, while advisors need organized information that can support meaningful planning conversations.

I continued developing the application after CS640 with greater attention to those real workflows, as well as user experience, administration, testing, and deployment.

Student Planning Experience

The student side is designed to turn a complex planning process into a guided sequence of smaller decisions. Rather than treating study abroad budgeting as a single calculation, the application connects student preferences, program information, travel costs, and financial estimates.

Student Planning

Guided Student Questionnaire

Students are guided through the information needed for their study abroad planning rather than being presented with one large form.

From an advising perspective, this creates a more structured student profile and captures information that can later support conversations about program fit, preferences, and affordability.

From an HCI perspective, breaking the process into smaller steps reduces the amount of information users need to process at one time and provides a clearer sense of progression.

Decision Support

Program Comparison & Date-Specific Airfare

Students can select multiple programs and evaluate them together rather than trying to remember information from separate program pages.

In this example, two spring break programs are selected. Because airfare can represent a meaningful part of the total cost of a short-term program, students can select travel dates and incorporate current Google Flights pricing into the comparison.

From a study abroad planning perspective, this creates a more realistic comparison than looking only at published program fees.

From an HCI perspective, the workflow moves from a simple selection task to a consolidated result. The application handles the underlying data retrieval and calculations while presenting information around the decision the student is trying to make.

Financial Planning

Transparent Budget Estimates

The application organizes study abroad expenses into understandable categories instead of presenting students with only one total.

This reflects an important part of study abroad advising: the advertised program price may not represent the student's full financial commitment. Airfare, transportation, housing, living expenses, and other costs can all affect affordability.

Showing how an estimate is constructed makes the result easier to understand and gives students better context for planning and advising conversations.

Advisor & Administrator Experience

I also wanted the application to reflect the administrative side of study abroad. Student planning tools are more useful when advisors can review relevant information, maintain institutional costs, and manage program data in the same system.

These features were designed around the idea that students and administrators may use the same underlying information differently. Students need guidance and comparison tools, while staff need concise records and workflows that support advising and program administration.

Administration

Central Advisor Dashboard

The administrator dashboard brings together the main staff-facing functions in one location.

From a study abroad administration perspective, this reduces the need to manage student information, program costs, and advising tasks across disconnected tools.

From an HCI perspective, the dashboard acts as a clear starting point for different administrative tasks and helps users understand where to go next without exposing unnecessary complexity all at once.

Advising

Student Profiles & Advising Context

Advisors can move from a list of students into an individual profile containing information collected during the student's planning process.

From an advising perspective, this creates continuity between what the student has already researched and what the advisor may need to discuss during an appointment.

From an HCI perspective, the system does not simply repeat the student interface for administrators. The same information is reorganized around the advisor's task: quickly understanding the student's planning context.

Institutional Data

Home Tuition Rate Management

Administrators can maintain tuition information used by the application rather than embedding those values directly into individual student calculations.

For study abroad offices, costs such as home tuition can depend on the institution's own policies and may change over time. Keeping these values in an administrative interface makes them easier to update consistently.

From a system-design perspective, separating institutional data from individual student inputs also makes the application easier to maintain and reduces unnecessary duplication.

Partner Cost Collection Workflow

Study abroad budgeting also depends on accurate information from external program partners and host institutions. I incorporated a workflow for requesting, receiving, and reviewing partner cost information.

The goal is to reduce the amount of manual back-and-forth required to collect updated program costs while still keeping staff involved in reviewing information before it becomes part of the advising process.

Administrative Efficiency

A structured request process can reduce reliance on disconnected spreadsheets, emails, and manual follow-up when gathering program costs.

Human Review

Submitted information is presented for staff review rather than being treated as automatically approved program data.

Workflow Visibility

Breaking the process into clear steps makes it easier for administrators to understand what has been requested, submitted, and reviewed.

Technology & Cloud Services

Preparing the portfolio version also gave me experience moving a database-backed application beyond a local development environment and deploying its components using cloud services.

GitHub

I use a private GitHub repository for source control, version history, and continued development of the application.

Render

The Flask application is deployed on Render so the portfolio version can run as a publicly accessible web application.

Aiven

The application connects to a managed MySQL database hosted through Aiven, allowing the application and database to run as separate cloud services.

Application architecture: Browser → Flask application on Render → MySQL database on Aiven

Development workflow: Private source repository on GitHub → deployment on Render

External data: User-selected travel dates can be used to retrieve current Google Flights pricing for program cost comparisons, with stored airfare estimates available when live pricing is unavailable.

Full-Stack Architecture

The application connects a browser-based interface to Flask application logic, a relational MySQL database, and selected external data services.

Front End

HTML, CSS, and JavaScript provide forms, navigation, filtering, comparison tools, dashboards, and other interactive elements.

Application Layer

Python and Flask manage routes, application logic, validation, authentication, data processing, and communication with the database.

Database Layer

MySQL stores interconnected information about students, programs, costs, budgets, advising, and administrative data.

External Data Integration

The application can incorporate current flight pricing for selected travel dates into program comparisons, connecting external information with internally stored program data.
